**FAIL S2: the server narrates, the console never draws it.**

| step | what was seen |

| campaign with a job description (Customer Success Manager / Lead / Partner), "Draft the role spec for X, approve it and start finding people" | model turn (16 to 19 s), card "Draft the role spec for X from its job description, approve it and start finding people" |
| Approve, in the browser, sampled every 1.5 to 3 s for the whole 43 to 63 s | **the card's button reads "Working" and nothing else changes until the outcome**; the article's HTML has `.lt-actions` with "Working" / "Not now" and no timeline list at all |
| the same approval, listening on the conversation's event stream (API) | 24 phase events arrive live: "Preparing the role spec", "Reading the job description", "Read the job description", "Drafting the role spec" with "Customer Success Partner, 3 s ... 42 s" every 3 s, "Approving the role spec", "Approved version 1", "Starting the search", "Search started", then the sentence; ids `approval:13`, `approval:13:read`, `approval:13:draft`, `approval:13:approve`, `approval:13:search` |

Root cause (read in `src/api/events.ts` and `agentEvents.ts`): `follow()` turns each SSE message into
`{ ...JSON.parse(data), id: last, type }`, where `last` is the numeric `lastEventId`. A phase event's own `id` (the line id) is in the
payload and is overwritten by that number, so `phaseOf` (`id: str(e.id) ?? phase`) falls back to the phase name and no line ever
has the id `approval:<seq>`; `approvalLines(turn.phases, seq)` is therefore empty and `ApprovalCard` shows no timeline. The unit
tests feed the reducer events with string ids directly, so they pass. (Every other phase line is also keyed by its phase name
instead of its own id, so two tool calls of the same kind in one turn share a line.)
